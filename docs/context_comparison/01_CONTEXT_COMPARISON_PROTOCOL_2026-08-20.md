## Motivation

Existing Original-M1, Original-M2, Hidden-M1, Hidden-M2, and EM3 results were
produced across partially different row populations and artifact forms. This
stage establishes an apples-to-apples Dev protocol before any new inference.
It asks whether Context routes differ in final candidate ranking and in how
they preserve, repair, or damage the shared Generic/Frequency decisions.

This is an evaluation/comparison stage. It is not authorization for new EM3
training, GPU inference, or Test evaluation.

## Metrics frozen for later evaluation

Primary: Macro-author Top1.

Secondary: Micro Top1, Ambiguous Top1, formal Conflict Top1, and candidate MRR
where complete ranks are genuinely available. Formal Conflict retains the
repository's existing `subset_membership` definition and is not `G != F`.

For each Context model C, report numerator, denominator, and percentage:

```text
SafePreserve = N(G✓ F✓ C✓) / N(G✓ F✓)
PureContextHarm = 1 - SafePreserve
FHarmRecovery = N(G✓ F✗ C✓) / N(G✓ F✗)
FRescuePreserve = N(G✗ F✓ C✓) / N(G✗ F✓)
```

Oracle opportunity diagnostic:

```text
Opportunity = G✗ AND F✗
              AND Gold in same-Pinyin history
              AND Gold in the common candidate pool
ContextOnlyRescueRate = N(Opportunity AND C✓) / N(Opportunity)
```

Gold-dependent opportunity fields are isolated post-hoc diagnostics and must
never become runtime features. Also report the complete eight-way G/F/C table,
per-author results, paired transitions, and—only after model/surface freeze—
paired bootstrap confidence intervals and exact McNemar tests.
