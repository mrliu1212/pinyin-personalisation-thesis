# Phase 4C Error Analysis Plan

## Purpose

Prepare human review of the completed Phase 4C transparency examples without
changing the benchmark, personal model, or evaluation. Reviewers should use
the evidence fields to describe observed cases; the extraction tool does not
assign an error category.

The evaluation artifact stores six selected transparency examples for each
personalised condition, rather than per-interaction traces for all 926 test
rows. This audit is therefore limited to those stored examples and must not be
treated as a prevalence estimate over the full benchmark.

## A. Improved cases

An improved case has `personalised rank < base rank`.

Review questions:

- Which global, Pinyin, or context evidence promoted the target?
- Was non-zero evidence specific to this exact context and Pinyin?
- Would global or Pinyin frequency alone explain the movement?
- Did competing candidates have weaker personal evidence, or merely no
  evidence?

Human notes should distinguish observed evidence from an inferred linguistic
explanation.

## B. Harmed cases

A harmed case has `personalised rank > base rank`.

Possible human-review categories are:

- `same_pinyin_lexical_confusion`
- `frequency_bias`
- `insufficient_context`
- `author_specific_vocabulary_bias`
- `other`
- `uncertain`

Review questions:

- Which competing candidate was promoted above the target?
- Did broad frequency outweigh evidence relevant to the occurrence?
- Was exact-context evidence absent or tied?
- Does the target appear characteristic of the test work but rare in training?

These labels must be entered by a reviewer. They are not generated by rules or
model inference.

## C. Wrong-user comparison

Compare shared stored examples under Zhu and Lu history:

- Does the target receive similar global or Pinyin evidence from both users?
- Does either history provide exact-context evidence?
- Do the two histories change rank differently despite similar total scores?
- Is the observed effect consistent with general lexical frequency rather than
  an individual preference?

The closeness of aggregate correct-user and wrong-user results is compatible
with the current model capturing general word frequency more strongly than
user identity, but individual examples require manual inspection before a
cause is assigned.

## Review file and command

Generate the deterministic JSONL review table:

```bash
.venv/bin/python -m audits.phase_04c_error_analysis
```

Output:

`results/audits/phase_04c/error_analysis_samples.jsonl`

Rows include context, Pinyin, target, ranks, Base candidates, and candidate-level
global/Pinyin/context evidence and personal scores. `human_category` and
`notes` are deliberately blank. Comparison rows contain both correct-user and
wrong-user candidate traces when the same interaction is stored under both
conditions.
